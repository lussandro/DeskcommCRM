## Incidente: `realtime` em crash loop

Sintoma: `restarts=39`, `tcp connect (db:5432): connection refused` e
`connection not available and request was dropped from queue`, com `db` `healthy`,
`restarts=0`, sem OOM (kernel e `docker inspect`), 5.4 GiB disponíveis.

Investigação:

| Medição | Resultado |
|---|---|
| `alpine` na rede `supabase_default`: `getent hosts db`, `nc -zv db 5432` | `172.18.0.3`, porta aberta |
| `show listen_addresses` | `*` |
| **dentro do `realtime`**: `getent hosts db` | **`::1 db.localhost`** antes de `172.18.0.3` |
| `/etc/resolv.conf` do `realtime` e do `alpine` | `search localhost baccosistemas.com.br`, `options ndots:0` |
| `/etc/resolv.conf` do host | `# Generated by NetworkManager` / `search localhost baccosistemas.com.br` |
| origem | `/etc/NetworkManager/system-connections/cloud-init-eth0.nmconnection`: `dns-search=localhost;` (ipv4 e ipv6) |

Causa-raiz: busca de DNS `localhost` injetada pelo cloud-init da imagem, propagada pelo Docker
a todos os contêineres; o resolvedor glibc do Realtime resolve `db` como `db.localhost` → `::1`.

Correção (na origem): backup do `.nmconnection` em `/root/`; `nmcli con mod "cloud-init eth0"
ipv4.dns-search "" ipv6.dns-search ""`; `nmcli device reapply eth0`;
`/etc/cloud/cloud.cfg.d/99-bacco-disable-network-config.cfg` com `network: {config: disabled}`;
`up -d --force-recreate`.

Depois:

```
host resolv.conf: search baccosistemas.com.br
realtime resolv.conf: search baccosistemas.com.br / options ndots:0
realtime getent db: 172.18.0.4 db
realtime: restarts=0 health=healthy
```
